DISTRIBUTED WORKLOAD DESIGN

Partition the data. Scale the work.

01 / DECOMPOSE

Partition for throughput

One compressed spectrum archive per job. Independent partitions distribute the expensive sliding-window search across cluster workers.

02 / SCHEDULE

Submit with Slurm / sbatch

Schedule independent batch workloads with Slurm, declare compute resources, and collect per-job outputs and logs for downstream reduction.

03 / REDUCE

Recover the global ranking

Merge per-job CSV outputs and rank spectral distances across all partitions to retain the 100 strongest candidate matches.

CLUSTER EXECUTION

From submission to scientific output.

RESOURCES

Explicit resource requests

The public HTCondor reference configuration requests 1 CPU, 2 GB memory, and 2 GB disk per task. It preserves an inspectable example of explicit batch-job resource sizing.

JOB I/O

Stage, execute, collect

The scheduler transfers each archive and the reference spectrum. A Bash worker extracts the batch, runs the R/FITSio search, and returns its result CSV.

IMPLEMENTATION

Cluster execution experience

The project used Slurm/sbatch scheduling as well as HTCondor batch execution. The public repository preserves the HTCondor submission path, the R/Bash search worker, and the retained Top-100 results.
